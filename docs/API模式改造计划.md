# API 模式改造计划

日期：2026-10-14。范围为 API 模式，Agent 与 Push 不在本轮重构范围内。

## 已确认的使用规则

- 只能修改和撤回自己发送的消息。同一会话的参与者、设备和本地历史同步更新，独立对话之间保持隔离。
- Manager 分别配置 @ 场景和独立会话默认系统提示词。独立会话默认为空，每个对话可继承、覆盖或显式清空。
- 默认上下文为最近 60,000 个 Unicode 字符，包括姓名、时间及元信息。超限裁剪最旧内容，撤回内容排除、编辑使用最新版本。
- 编辑后不自动重新生成，由用户手动触发。
- AI 身份可配置和修改显示名称与头像，保留稳定内部 ID。
- 输入 @ 时显示可调用身份候选。切换聊天对象列表显示 AI 身份头像名称，不添加身份类别标签。
- 独立对话支持新建、切换、改名、模型选择和提示词设置。首轮回复成功后生成默认标题，手动名称不被覆盖。

## 执行顺序

1. 服务端：配置/数据库兼容迁移、身份头像更新、字符预算上下文、场景提示词、线程设置、标题生成、重新生成以及消息修订日志。
2. 客户端核心：身份和线程模型、联系人入口、修订事件和离线增量对账、本地历史同步。
3. 客户端界面：@ 补全、目录和工具栏、提示词编辑、消息编辑/撤回与重新生成。
4. Manager：模式专属配置、头像选择、显示名称、两种提示词和字符预算，并保持各 VPS 配置独立。
5. 验证：Go 回归测试、Flutter analyze/相关测试、Windows 构建、使用文档。iOS 需 macOS/Xcode 真机验证。

消息修订保持原消息 ID 与 seq，独立 revision 游标保证离线客户端能补齐编辑和撤回。WebSocket 使用 message.updated，不把修订计作新消息。

## 执行状态（2026-10-22）
