# 自动化调用审计与更新说明

更新日期：2026-10-08。

## 本轮修复

- 恢复服务端 `api.go` 的 UTF-8 编码和 Go 语法，保留已有未提交功能。
- 异步提及自动化身份时，模型发现失败、调用失败或 Agent 地址缺失会在聊天中返回友好提示。详细诊断写入服务端日志。
- 错误消息带有 `error: true`，不会进入下一轮模型上下文。
- 模型 API 地址与 CLI Proxy 管理页面链接分开使用。
- CLI Proxy 安装保留已有 `config.yaml` 和 `docker-compose.yml`，只为缺失文件创建配置。只有首次创建配置才生成新密钥。
- 编辑自动化身份前，Manager 从当前 VPS 配置读取实际客户端 API Key；不会把上游模型密钥误当作客户端访问密钥。
- API/Agent 身份有独立的 Test API 按钮，通过 SSH 从 VPS 请求 `/v1/models`。HTTP 失败保留退出码；Push 模式不执行模型测试。
- Agent 请求始终携带身份、当前用户、会话和接收者标识，不再依赖是否配置模型；历史用户消息带稳定的用户标识。

## 更新和排查

1. 关闭旧 Manager，使用 `manager/build/windows/x64/runner/Release` 中新构建的管理器。移动程序时复制整个 Release 目录，包含 DLL 和 data。
2. 连接目标 VPS，在 Deploy 页面选项目根目录并重新部署 QuickConect 服务端。仅替换 Windows Manager 不会更新 VPS 的 Go 服务。
3. 在自动化身份的 API 地址填入模型接口，例如 `http://127.0.0.1:8317/v1`。管理页面链接只用于打开管理面板。
4. 用 Test API 检查 `/v1/models`。401 通常需要核对实际访问密钥；空模型目录通常需要先在 CLI Proxy 中完成提供商登录或配置。
5. 保存自动化身份后，将配置写入 VPS 并重启 QuickConect，再测试 `@名称`。失败时查看聊天提示及服务端日志。

已有配置的管理密钥可能经过哈希，无法从配置反推出原始口令。Manager 显示的本地缓存管理密钥可能与已有远端配置不同，此时使用原管理密钥。

若此前旧版安装已经覆盖远端配置，本轮修复只能避免继续覆盖；原配置需从备份恢复或重新配置。

## 验证范围与剩余功能

服务端 Go 测试、Manager 分析/测试/Windows 构建、客户端分析和常规测试通过。生产环境媒体诊断默认跳过，需明确启用：

```powershell
flutter test --dart-define=QC_RUN_PROD_DIAGNOSTICS=true test/prod_diag_test.dart
```

Agent 元信息是接入协议的一部分，不等同于实际长期记忆、联网搜索或服务器执行能力。实际 Agent 运行时仍需落实这些能力及按用户隔离的存储。客户端独立 AI 对话目录、新建对话和模型选择入口也还需要完成接入，不能视为整个 AI 功能已经完成。

iOS 真机权限、保存及渲染行为仍需在 macOS/Xcode 环境验证。
