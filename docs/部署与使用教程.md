# QuickConect 部署与使用教程

> 面向：项目的所有者与使用者。假设读者不写代码，所有操作按步骤照做即可。
>
> 系统组成：上海 VPS 上的服务端 + 四端客户端（Windows / Android / iPhone / iPad）+ ntfy 推送铃。
>
> 项目根目录：`E:\vibecoding-project\quickconect`（本文简称「项目目录」）。

---

## 1. 系统总览

```
你的 VPS (https://IP:8443)  ←—→  Windows 客户端 / Android 客户端 / iPhone·iPad 客户端
        ↓
   ntfy.sh（推送铃：App 被系统杀掉后，替你喊一嗓子「有新消息」）
```

- **数据在哪**：全部聊天记录和文件在 VPS 的 `/var/lib/quickconect/`（一个数据库文件 + 媒体目录）。备份 = 备份这个目录。
- **谁信任谁**：客户端只信任自签证书的指纹，浏览器无法访问，外人也进不来。

## 2. 服务器运维（管理员手册）

### 2.1 日常命令（SSH 登录 VPS 后执行）

| 操作 | 命令 |
|---|---|
| 看运行状态 | `systemctl status quickconect` |
| 重启服务 | `sudo systemctl restart quickconect` |
| 看日志 | `sudo journalctl -u quickconect -n 50 --no-pager` |
| 建新账号 | `sudo /opt/quickconect/quickconect-server adduser -config /etc/quickconect/config.yaml -name 用户名 -display 昵称 -password 密码` |
| 健康检查 | `curl -sk https://127.0.0.1:8443/healthz`（返回 `{"ok":true}` 即正常） |

### 2.2 升级 / 重新部署（一键）

在你自己的电脑上（Git Bash），项目目录下执行：

```bash
bash deploy/deploy.sh <服务器IP> <SSH用户> <SSH私钥路径> [端口]
# 例：bash deploy/deploy.sh 124.223.44.151 ubuntu ~/.ssh/tencent_cloud.pem 22
```

脚本会自动：交叉编译 Linux 二进制 → 上传 → 安装并重启服务。**重复执行即升级**，聊天数据不受影响。

### 2.3 换 VPS（数据迁移）

1. 在旧 VPS 上打包数据：`sudo tar czf /tmp/qc-data.tgz -C /var/lib quickconect`
2. 把 `qc-data.tgz` 拷到新 VPS 同位置并解压：`sudo tar xzf /tmp/qc-data.tgz -C /var/lib`
3. 在新 VPS 上照常执行一键部署（2.2）。账号、消息、文件原样保留。

### 2.4 备份与恢复

- **备份**：定期在 VPS 上执行 `sudo tar czf ~/qc-backup-$(date +%F).tgz -C /var/lib quickconect`，建议再把备份文件下载到本地（scp 或宝塔等面板）。
- **恢复**：解压到 `/var/lib/` 后重启服务 `sudo systemctl restart quickconect`。

### 2.5 证书（了解即可）

- 服务器使用自签证书，绑定服务器 IP，有效期 5 年，一般不用管。
- **重要**：客户端校验的是「服务器证书」的指纹。若将来在服务器上重新生成证书，所有客户端要重新粘贴一次新指纹。查看指纹：
  `sudo openssl x509 -in /etc/quickconect/server.crt -noout -fingerprint -sha256`
- 换了服务器 IP 也必须重新生成证书（指纹绑定 IP SAN）：删除 `/etc/quickconect/server.crt` 和 `server.key` 后重跑一键部署。

## 3. Windows 客户端

### 3.1 安装 / 更新

- 程序位置：`app\build\windows\x64\runner\Release\quickconect_app.exe`，**整个 Release 文件夹**拷走即可运行，无需安装器。
- 更新：用新构建的 Release 文件夹覆盖旧文件夹。

### 3.2 登录

| 字段 | 填什么 |
|---|---|
| 服务器地址 | `<服务器IP>:8443` |
| 用户名 / 密码 | 管理员发的账号 |
| 证书指纹 | 管理员提供的 64 位十六进制串（https 必填，填错会握手失败） |

### 3.3 使用要点

- **外观定制**：设置 → 外观定制。9 项颜色可改，实时预览；内置 5 套预设；调好后「保存为预设」起名保存。
- **窗口**：顶栏可拖动移动窗口，右上角最小化/最大化/关闭。
- 收到消息时若不在对应聊天页，会弹系统通知；点通知直达该会话。

## 4. Android 客户端

### 4.1 安装

1. 把 `app\build\app\outputs\flutter-apk\app-release.apk` 传到手机（微信文件传输/QQ/数据线均可）。
2. 手机上点开 APK 安装，系统提示「未知来源应用」时选择允许。
3. 登录方式与 Windows 相同（服务器地址、账号、证书指纹）。

### 4.2 通知与后台（国产手机重点）

- 首次启动时允许通知权限。
- **电池优化白名单**（强烈建议）：设置 → 外观与通知相关入口，或系统设置里搜索「电池优化 / 省电策略」→ 找到 QuickConect → 选「不限制 / 允许后台运行」。不同品牌叫法不同（小米：省电策略-无限制；华为：启动管理-手动管理并三项全开；OPPO/vivo：允许后台运行 + 关闭深度睡眠）。
- **前台服务开关**（设置里）：开启后通知栏常驻「保持连接中」，退到后台消息依然实时。若你主要用「打开才看」，可以不开。
- **离线兜底**：就算进程被杀，ntfy 推送铃也会通知你（见第 6 节），打开 App 自动补齐消息。

### 4.3 更新

新 APK 直接覆盖安装即可，聊天数据在服务器，本地无损失。

## 5. iPhone / iPad 客户端（免费自签方案）

### 5.1 一次性准备（每台设备 + 电脑）

1. 准备一个**专用的免费 Apple ID**（不要用个人 iCloud 主账号）。
2. Windows 电脑安装 [Sideloadly](https://sideloadly.io) 或 AltServer。
3. 数据线连接 iPhone 与电脑。

### 5.2 安装 SideStore（每台设备一次）

1. 电脑上用 Sideloadly 把 SideStore 的 IPA 装进手机（SideStore 官网下载 IPA；期间会要求输入专用 Apple ID 与密码）。
2. 手机上：设置 → 通用 → VPN 与设备管理 → 信任对应的开发者证书。
3. 打开 SideStore，按引导完成设备配对（之后即可脱离电脑自续签）。

### 5.3 安装 QuickConect（IPA 来源见 5.5）

1. 把 `quickconect-ios-unsigned.ipa` 通过 AirDrop/文件传到手机。
2. 打开 SideStore → 「+」号 → 选择该 IPA → 用专用 Apple ID 签名并安装。
3. 同 5.2 第 2 步信任开发者证书，然后打开 QuickConect 登录。

### 5.4 自动续签与版本更新

- **续签**：SideStore 会自动为已装 App 续签（7 天有效期）。正常情况无感；若 App 打不开，重连电脑用 Sideloadly 重装一次即可。
- **版本更新（重要）**：续签 ≠ 更新。出新版本时，需要在 SideStore 里重新导入新 IPA 安装一遍（数据在服务器，无损失）。

### 5.5 获取 IPA：GitHub Actions 云构建

1. 在 GitHub 新建仓库（私有即可），把项目推送上去：
   ```bash
   cd 项目目录
   git init && git add -A && git commit -m "init"
   git remote add origin https://github.com/<你的用户名>/<仓库名>.git
   git push -u origin main
   ```
2. GitHub 网页 → 你的仓库 → **Actions** 标签 → 选 **Build iOS IPA** → **Run workflow**。
3. 构建完成（约 10–20 分钟）后，进入该次运行，下载 artifact「quickconect-ios-unsigned」。
4. 以后每次要发 iOS 新版：把最新代码 `git push` 后重跑一次 workflow。

### 5.6 TrollStore 机会（如果能用上，跳过一切续签）

若某台设备的 iOS 版本在 **14.0–16.6.1 或 17.0** 范围内（设置→通用→关于本机查看），可以安装 [TrollStore](https://github.com/opa334/TrollStore) 永久签名，App 永不过期、无需续签。安装 TrollStore 本身请按其仓库说明操作。

## 6. 推送铃 ntfy（离线通知，各端通用）

1. 手机安装 **ntfy** App：iPhone 在 App Store 搜「ntfy」；安卓建议从 [ntfy GitHub Releases](https://github.com/binwiederhier/ntfy/releases) 下载 APK（无谷歌服务的手机也能用）。
2. 打开 QuickConect → **设置 → 推送铃** → 用 ntfy App 扫描页面上的二维码（或复制链接后在 ntfy App 里订阅）。
3. 点「发送测试通知」验证：ntfy App 里应立刻弹出「QuickConect 测试」。
4. 原理：QuickConect 被系统杀掉后，服务器发一条不含任何内容的计数提醒给 ntfy，由它唤醒你——看到通知后打开 QuickConect 即自动补齐消息。

## 7. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 登录报「握手失败 CERTIFICATE_VERIFY_FAILED」 | 证书指纹不对或不完整。向管理员要**服务器证书**指纹（64 位十六进制），整段重新粘贴。 |
| 登录报「无法连接服务器」 | 服务器地址写错 / 服务器挂了 / 安全组没放行 8443。先在 VPS 上执行健康检查（2.1），再查腾讯云控制台的安全组规则。 |
| 收不到任何通知 | ① 手机通知权限；② ntfy App 是否订阅成功（设置→推送铃→发测试通知）；③ 安卓杀后台 → 白名单+前台服务；④ iOS 免费签名的正常限制，靠 ntfy 兜底。 |
| 图片显示「加载失败，点按重试」 | 点一下通常就好了。若反复出现，查电脑日志文件 `%TEMP%\quickconect_client.log`（手机端为应用沙盒内，需反馈给开发者）。 |
| 传大文件很慢 | VPS 带宽限制。单文件上限 100MB，每人总配额 10GB，均可在 `/etc/quickconect/config.yaml` 调整后重启服务。 |
| 忘记密码 | 管理员重新 adduser 一个新账号；或让管理员改数据库（暂无改密命令）。 |
| iOS App 打不开 | 7 天签名过期，重连电脑用 Sideloadly 重装（5.4）。 |

## 8. 已知限制与升级路径

| 限制 | 说明 | 解除方式 |
|---|---|---|
| iOS 无系统推送 | 免费 Apple ID 签名拿不到 APNs，靠「本地通知 + 静音保活开关 + ntfy 铃」三层补位 | 购买 Apple 开发者账号（¥688/年），架构已预留，随时可切换 |
| iOS 更新要手动 | 新版本需在 SideStore 重新导入 IPA | 同上 |
| 服务器证书绑定 IP | 换 IP 需重新生成证书并更新所有客户端指纹 | 使用域名 + 正式证书（需备案）可免 |
| 群聊未开放 | 架构已预留，打开即用 | 提需求即可 |

## 9. 目录速查（开发/维护者）

```
quickconect/
├── server/                  Go 服务端源码
├── app/                     Flutter 客户端源码（四端共用）
├── deploy/
│   ├── deploy.sh            一键部署入口（本机执行）
│   ├── install.sh           服务器安装脚本（幂等，可重复跑）
│   ├── gen_certs.sh         手动生成证书（一般用不到，install.sh 内置）
│   └── config.example.yaml  配置样例
├── dist/                    构建产物（服务器二进制）
├── .github/workflows/ios-build.yml   iOS 云构建工作流
├── docs/设计方案.md         全部设计决策记录
└── .tools/                  本地构建工具链（Go / Flutter / JDK / Android SDK）
```

**改代码后的标准流程**：改 → `flutter analyze` + `flutter test` + 服务端 `go test` 全绿 → `flutter build windows --release` / `flutter build apk --release` → `bash deploy/deploy.sh ...` 更新服务器 → 各端安装新包。
